# Security policy

**Current stage:** local fictional/sanitized prototype. **Do not** submit real customer records, access keys, production logs or sensitive personal information to this public repository or any public demo.

If you discover a possible security vulnerability, use GitHub's **private vulnerability reporting** mechanism when enabled; otherwise, contact the repository maintainer through a privately agreed communication channel. Do **not** put exploitation details, credentials, screenshots containing sensitive data or private customer information into a public issue.

There is no promise of production support, uptime or a security certification at this stage. Before a customer pilot, the project must qualify identity/permissions, tenant separation, secure intake, approved source handling, encryption/keys, retention, incident response, evidence integrity and independent outcome verification.
