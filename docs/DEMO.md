# Fictional Acme demonstration — what it proves

**All names and data in this example are fictional.** This is a local offline regression fixture, not an authorized customer deployment.

## The scenario

A support workflow claimed that request `req-101` was complete, but the independent supplied state observation did not contain the required result at the deadline. The system performs five saved local stages:

1. **CATALOG** — identify and hash-check the fictional source set.
2. **INVESTIGATE** — inventory documented claims and citations deterministically (no qualified native model inference in this v0.7 mission).
3. **SHADOW** — independently replay a frozen supplied offline observation in separate Python and JavaScript verifiers.
4. **QUALITY** — check report claims, source bindings and proof limitations.
5. **DRAFT** — prepare a checksum-bound **internal** assessment; founder release remains ungranted.

**Result:** `FAIL` for the fictional required state (`REQUIRED_STATE_NOT_OBSERVED_AT_DEADLINE`). The failure is a successful *detection* of unsupported completion, not a repaired production system.

## What observers should understand

The important outcome is not the count of worker icons or how futuristic the interface looks. It is that source and task history can be replayed, a false completion can be caught by a distinct verifier, and a report does not silently turn missing evidence into 'verified'.

## What the demonstration does not prove

Production login, customer data permissions, real model investigative quality, live read-only business observations, independent authentication of external state, safe autonomous production edits, or Windows hardware qualification. These are future acceptance gates.


## Interactive public presentation — 2026-10-30

The [browser prototype](../index.html) presents this published scenario with newly
authored synthetic records. The original facts retained are Acme request `req-101`,
a completion claim, an absent required state at the deadline, and the resulting
`REQUIRED_STATE_NOT_OBSERVED_AT_DEADLINE` failure. Additional sample lines, names of
fixture sources and illustrative timeline details are presentation examples, not
recovered historical logs.

No original private model output, native worker message, customer identity,
approval record or internal database has been copied into this repository. The
public repository contains no verified historical event payload to replay. Its
replay control advances a **synthetic example history**, and the crown-free colony
map projects that example; it does not show live agents.

The client-side comparison is a small demonstration of the documented outcome
contract. It is not a port of the canonical Shadow engine, and it does not create
another Store, scheduler or worker system. A complete supplied fictional observation
can establish that the required state was absent at the deadline. Missing or
insufficient observations remain `NOT ASSESSED`; they do not become a verified
failure. An explicitly changed observation can illustrate `PASS` without changing
the baseline case.

Report export includes the fictional proof class, selected observation, source
identities/hashes, citation references and unresolved questions. It is always an
**internal, unapproved demonstration report**. No Quality or Queen verdict is
fabricated. See [the prototype guide](PROTOTYPE.md) for the reproducible walkthrough.
